# 小红书与抖音检索采集增强设计

## 目标

让 Luz-Crawl 在公开页面优先的前提下，稳定完成小红书笔记、抖音视频的搜索、详情、作者、发布时间、正文、媒体和已加载评论采集；当站内搜索不可用或结果弱时，自动拆分关键词并切换公开索引路线，保留每一步的检索词和证据。登录内容只在用户明确授权并提供已连接浏览器时采集，并与公开结果分开标记。

## 约束与边界

- 只读取真实浏览器已呈现的页面状态、JSON-LD、初始化状态和可见 DOM。
- 不接入签名破解、逆向接口、代理池、Cookie 导出、验证码绕过或未授权 API。
- 评论字段表示本次页面实际加载的评论；显示总数不等于已抓全，必须保留覆盖状态。
- 自适应批量根据候选数量、详情成功率和页面预算扩展，仍受单任务硬上限和站点限制约束。
- 每个字段保留来源类型和原始值，无法确认的时间不猜测。
- 结果状态必须区分 `captured`、`partial`、`awaiting_user`、`blocked`、`failed`，把登录、验证、限流和空结果分别记录。

## 方案

### 1. 统一社媒数据模型

新增 `lib/social-schema.mjs`，提供纯函数：

- `parseSocialTime(value, now, timezone)`：支持 ISO、Unix 秒/毫秒、绝对日期和“刚刚/分钟前/小时前/昨天”等相对时间；返回 `{ raw, iso, timezone, precision, source }`，无法确认时返回 `iso: null`。
- `normalizeSocialRecord(input)`：把页面状态和 DOM 结果整理为统一的 `post`、`account`、`comments`、`coverage` 和 `field_sources`。
- `dedupeSocialComments(comments)`：优先使用评论 ID，其次使用作者、时间和正文指纹，兼容虚拟列表重复渲染。
- `expandSocialQueries(request, options)`：保留原词，拆出主题、对象、动作、场景、平台、同义词和排除词，生成有限的中文、英文和口语查询，并返回每个查询的目的和证据要求。
- `selectAdaptiveBudget({ candidates, read, comments, budget, failures })`：根据候选量和成功率计算详情与评论预算，返回硬上限、下一批数量和停止原因。

字段至少包含：内容 ID、原始 URL、标题、正文、作者昵称、作者 ID、作者主页、原始时间、ISO 时间、时区、时间精度、互动数、标签、媒体、评论正文、评论作者、评论主页、评论时间、评论点赞、父评论、已加载数、页面显示总数、是否完整、登录/验证状态、检索词和字段来源。所有数值保留页面原始文本和解析值。

### 2. 页面状态与 DOM 双路径解析

扩展 `lib/extract-page.mjs`：

- 小红书优先读取 `window.__INITIAL_STATE__.note.noteDetailMap`，其次读取 JSON-LD 和可见 DOM；抖音优先读取页面暴露的 JSON-LD/初始化状态，缺失时使用稳定的 `data-e2e`、作者链接、时间和评论容器选择器。
- 解析结果先进入统一 schema，再写入现有 `post`、`items` 和 `comments`，保持旧字段兼容。
- 作者和评论统一输出 `account`（name、handle/id、profile_url）；正文、作者、时间、互动、评论都附 `field_sources`，来源只允许 `page_state`、`json_ld`、`dom`、`visible_text`、`observed_media`。
- 对相对时间记录采集时刻和时区；只有页面给出可确认日期才写入 ISO 时间。
- 详情 URL 必须确认目标内容 ID；页面壳、登录页和搜索卡片不能升级为正文成功。

### 3. 搜索规划与候选处理

在 `lib/search.mjs` 接入社媒查询规划：

1. 先执行原始查询和一组有限的功能/对象/场景变体。
2. 从搜索卡片正文和标签提取新词，只允许一轮相关词补搜；每个补搜词保存来源候选和命中文本。
3. 以规范化内容 URL 去重，按主题命中、标题/正文证据、时间新鲜度、互动信号和作者信息完整度排序；过滤导航、推荐、广告、登录和跨域伪结果。
4. 结果数量不足时切换 Bing `site:` 公开索引；小红书/抖音站内结果仍需回到原站详情页核验。
5. 详情打开失败、被删除、无正文或临时不可用时继续尝试下一个候选，并在 `attempts` 记录失败原因；登录、验证、限流则停止该路线并返回可操作状态。

GitHub 继续使用现有的功能/技术栈/语言拆词和 GitCN 等候选路线，并补充同一过滤、去重和详情失败继续策略；不合并无许可证或逆向接口项目代码。

### 4. 自适应批量与评论覆盖

扩展 `lib/capture.mjs`：

- 搜索阶段使用小滚动预算快速收集候选；详情阶段按候选量动态增加打开数量，至少保留一批失败候选的补偿空间。
- `--comments` 只在评论容器内滚动，按评论 ID/指纹去重；虚拟列表重复项不增加加载计数。
- 连续无新评论、达到硬上限、到达页面末尾、登录/验证/限流或操作预算耗尽时分别记录 `stop_reason`。
- 输出 `comments_coverage`：`loaded`、`displayed_total`、`all_comments_verified`、`batches`、`stop_reason`；永远不把显示总数当作已抓全。
- 公开模式和授权浏览器模式在结果中分别写入 `access_mode`，默认不持久化账号、Cookie 或令牌。

### 5. 插件与文档

扩展 `browser-extension/popup.html`、`popup.js` 和必要的后台状态消息：

- 显示浏览器连接、公开/授权模式、当前任务状态、检索词数量、候选/详情/评论进度和停止原因。
- 提供“自适应批量”“仅公开页面”“使用已连接浏览器”三个明确状态，不提供 Cookie 或代理配置。
- 文案只保留功能、作用和操作方法；`README.md`、`SKILL.md`、插件帮助页删除作者、来源和重复背景，保留许可文件。
- 版本号随本次大改升至 3.3.0，插件 manifest 和包元数据一致。

## 数据流

```text
用户请求
  -> expandSocialQueries / githubQueryPlan
  -> 站内搜索 -> Bing/GitCN 等公开索引备用
  -> 候选 URL 规范化、去重、相关性排序
  -> 详情页状态/DOM 解析 -> normalizeSocialRecord
  -> 评论容器自适应滚动 -> dedupeSocialComments
  -> 证据、状态、覆盖率写入 content.json / HTML / manifest
```

## 错误处理

- 搜索页可读但无合格候选：记录 `no_candidates`，继续下一关键词或备用索引，不返回伪成功。
- 详情不可用：记录候选级失败并继续，最终以成功详情数和失败原因决定 `captured` 或 `partial`。
- 登录或验证：返回 `awaiting_user`，保留手动继续 URL；未获用户授权不切换到登录态。
- 限流或访问拒绝：记录页面可见证据和冷却信息，停止当前路线，避免重试放大限制。
- 状态字段解析失败：保留原始文本与 `parse_error`，不填猜测值。

## 测试与验收

新增单元测试覆盖：时间解析、关键词扩展、统一作者/评论结构、虚拟评论去重、自适应预算、详情失败后继续、登录/验证/限流状态和 GitHub 公开索引过滤。使用固定页面快照和模拟 `capturePage`，不依赖账号或外网。

验收标准：

1. `npm test` 全部通过，原有 GitHub 和浏览器生命周期行为不回归。
2. 小红书、抖音测试数据同时有原始时间、ISO 时间、作者主页、正文、评论来源和覆盖率。
3. 搜索输出列出实际搜索词、补搜词、候选证据、详情尝试和停止原因。
4. 任何登录、验证、限流或空结果均不会被标记为成功正文。
5. 插件可显示连接与采集状态，文档只保留功能、作用、操作方法。
6. `git diff --check`、Luz-Crawl 检查、Luz-Dev 技术方案检查和文档检查通过。

## 不做的事

本次不实现平台私有接口、签名计算、验证码绕过、代理池、账号池、全量评论保证、音视频转写或 OCR；这些能力不属于公开页面证据链，且会降低结果可验证性。
