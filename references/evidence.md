# 归档与验收

## 输出

输出根下只放“序号-主题”任务文件夹，`raw/` 放全部爬取内容和机器记录，总结页与 `raw/` 同级；目录全貌见 [SKILL.md](../SKILL.md)。

每个任务自动生成总结页（`序号-主题.html`：标题加带表题的采集结果表，没有内容的节不写，版式与前置检索结论页相同），`begin` 建任务时写出，每次采集重写，`summary` 可随时重建。search、capture、batch、browser 的结果分别保存 JSON，放在任务的 `raw/` 里。

每个页面存档的文件直接放在“四位序号_标题”文件夹（如 `0001_页面标题`）：content.json（正文与字段）、manifest.json、identity.json、snapshots/（每轮滚动的 JSON 与 HTML）、page.png（截图）、media/（已下载媒体）和页面 html。manifest.json 的文件路径相对该文件夹；记录规范 URL、实际 URL、请求 URL、平台、路线、状态、停止原因、正文范围、媒体统计、`captured_at`、`extractor_version` 和每个文件的 SHA-256。verify 只检查本地文件与记录一致，不证明网页真实性或内容完整。引用字段与来源评估见 [research-method.md](research-method.md)。

## 与 WARC 的关系

本技能保存的是浏览器渲染后的 DOM、可见文字和截图，不保存 HTTP 请求与响应原文及头部，所以不是 WARC（ISO 28500；[WARC 1.1](https://iipc.github.io/warc-specifications/specifications/warc-format/warc-1.1/) 的记录含 `WARC-Date`、`WARC-Target-URI`、`WARC-Payload-Digest`）。manifest 的 SHA-256 能发现本地文件被改动，但没有可信时间戳，也无法证明页面当时的服务端响应。需要诉讼或公证级保全时，另用 WARC 工具和第三方时间戳，不用本技能的归档代替。

## 内容边界

- 搜索结果、页面外壳和推荐卡片不是正文。
- 视频简介不是完整视频；当前加载的评论不是全部评论。
- 只保存浏览器实际看到且用户有权访问的媒体。
- DRM、过期签名、无直链或权限不足时保留缺项，不绕过限制。
- 单个达到 1 MiB 的新 JSON 或 HTML 快照以 gzip 无损保存。按 content.json 里的快照路径读取，扩展名为 .gz 时解压。清单校验保存文件的 SHA-256。
- 把仅供本任务阅读的 PDF、压缩包和其它原始下载放在任务的 `raw/download-cache/`，写完后再从 .part 改为正式文件名。生成离线报告所用媒体保存在页面归档内。合并视频成功后，可回收的大音视频分轨进入缓存，来源和哈希仍记在 downloads.json。
- 完成本任务的阅读和摘录后运行 `summary <任务目录>`。有正文且总结页写入成功时，清理当次开始前已完成、单个达到 8 MiB 的缓存文件，返回实际回收的字节数。遇到读取告警、正在下载或要求保留原件时可继续留存。`--keep-raw` 重建总结并保留缓存。

## 状态

| 状态 | 含义 |
|---|---|
| captured | 目标正文已读取并达到本次范围 |
| partial | 已读取部分内容，仍有缺项或预算耗尽 |
| awaiting_user | 等待用户登录或完成验证 |
| blocked | 被限流、权限、验证或目标缺失阻止 |
| failed | 浏览器、传输或归档执行失败 |

不要把任何状态称为“全站完整”。没有明确核验时，评论、附件、视频字幕和站点数据都按已取得范围报告。

## 续接与校验

同一任务再次 capture 同一 URL 不改动旧存档，而是另存为新序号的存档（manifest 与 identity 写 `recapture_of`）；加 `--resume` 才先核验再续接该网址最新的一份。旧成功不能覆盖当前错误页、登录页或不完整结果。

登录、验证和限流任务保存 task_id；用户处理后运行 continue。批量只停止受阻站点，其余项目继续。不要重放结果未知的写操作。

## 旧版目录

下划线写法的任务文件夹（`NNN_主题`）保持原名，仍可读取、续接和生成总结，也计入新任务的序号。更早的版本把任务文件夹放在 `<输出根>/raw/` 下、页面存档里再套一层 `raw/`、网页 html 散落在输出根，这些目录同样可读取和续接；`scripts/migrate_layout.py` 把它们整理成上面的形状（任务沿用原名，只有改号的文件夹用新写法；默认只预览，`--apply` 才执行，`--revert 移动记录.json` 撤回）。迁移后，仍写着旧绝对路径又不能改写的记录（被审批冻结的前置检索记录）由 `crawl_preflight.py` 读取时按 `000_目录整理记录/raw/旧路径映射.json` 解析到新位置；映射里没有的旧路径照常报错，记录本身不变。输出根之外的项目目录用 `--rewrite-with 移动记录.json --extra-root 目录` 改写，审批绑定的文件不动。

## 经验

有效路线、关键词和失败原因可写入 data/memory/；不保存密码、Cookie、令牌、私人路径或私人内容。
