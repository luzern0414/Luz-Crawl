# 分类、检索与交付

## 任务目录

输出根由用户指定，必须在技能目录之外。一个需求只用一个任务目录，跨站点、关键词和续接共用返回的 TASK_FOLDER。没有明确分类时直接使用输出根，不按平台创建顶层目录。

## 关键词

保留用户原词，再补充同义词、行业词、英文术语、实现方式和交付形式。每轮只增加能解释结果的词。没有相关候选时换功能词、技术词或平台，不用弱结果凑数量。

## 多站搜索

先从网站库选择相关入口，再写入 platform-plan.json。逐站确认 page、search、detail、statistics、media 的状态。只有验证过的路线才加入运行 catalog；网站首页可读不代表搜索或详情可用。

需要多站、多词时使用 collect --file 或 batch。所有搜索与采集结果写入同一任务目录，登录、验证和限流只停止对应站点。

## 候选到详情

先收集、规范化和去重候选 URL，再逐条读取目标详情。核对标题、正文、日期、内容 ID、媒体和已加载评论。推荐卡片、导航、搜索摘要和平台介绍不能代替原文。

search --read 0 只建立候选池；选出相关 URL 后再 capture。实操内容要有实际步骤或可演示操作；广告、招生和引流内容不算教程。

## 交付

- 文本：保留实际读取范围和缺项。
- 视频：分别核验文件、MIME、哈希、画面和音轨。
- 企业或公告：字段、单位、时间和页面分别记录。
- 设计：图片、标题、链接和提示词保持对应。
- 所有任务：分开报告搜索、正文、媒体、评论、完整性和关闭状态。

未经核验的内容标为候选或 partial，不能写成完整结果。
