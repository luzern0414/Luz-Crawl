# 来源评估与调研结论

评估前先执行 [尽责调查与经验复用](research-diligence.md)：按问题发现来源、查经验、分轮读后补搜，完整保留候选与停止原因。以下来源级别不替代相关性、适用范围和发布主体核验。

## 来源分级

结论只靠一级和二级来源；三级用来找线索，四、五级不单独支撑任何结论。

| 级别 | 来源 | 用法 |
|---|---|---|
| 一 | 法律法规与标准发布方、RFC 等规范、平台和厂商官方文档、官方仓库的 README 与发布说明 | 规则、接口、版本和数字的依据 |
| 二 | 政府采购与招标公告、企业官网、官方公告与 Issue、论文原文 | 事实与做法的依据，核对日期与适用范围 |
| 三 | 成熟技术社区长文、行业协会与咨询机构报告、同类产品文档 | 找同类做法与术语；关键数字回到一、二级核对 |
| 四 | 博客、问答、短视频、笔记与评论 | 场景、措辞和候选；不作依据 |
| 五 | 搜索摘要、搜索引擎的回答卡、聚合与转载站 | 不算来源，只用来找到原文 |

## 评估问题

沿用 [CRAAP](https://library.csuchico.edu/sites/default/files/craap-test.pdf) 的五项，并按 [SIFT](https://hapgood.us/2019/06/19/sift-the-four-moves/) 横向核对：

| 项 | 要回答 | 记录位置 |
|---|---|---|
| 时效 | 何时发布或更新；对本题是否过时；版本是否对应 | 引用字段“发布时间”；补充信息的 `summary` 写明版本 |
| 相关 | 是否回答本次缺的信息；读者与深度是否匹配 | `applies_to` |
| 权威 | 作者或发布方是谁，凭什么说这件事；是否第一手 | 引用字段“作者或发布方”，来源级别 |
| 准确 | 数据出处是否可查；能否在另一来源核对 | 另取一个来源核对，写入 `summary` |
| 目的 | 在教学、销售还是宣传；有无利益关系 | 不采用时写 `reason` |

不要仅凭域名后缀判断权威；先找原始发布方（SIFT 的“追溯到原始出处”），无法找到原文的内容按四级处理。

## 引用字段

每条引用的来源至少能回答下列字段。采集已保存的字段不手写；页面没有给出的字段留空，不猜。下列文件都在页面存档文件夹（`<任务目录>/raw/NNNN_标题/`）里。

| 字段 | 取自 |
|---|---|
| 标题 | `content.json` 的 `title` |
| 作者或发布方 | `post.account.name`、站点名称 |
| 发布时间 | `post.published`（原始值、ISO 时间、精度和来源）或 `items[].time`，仅在页面给出时 |
| 网址 | `canonical_url`、`resolved_url` |
| 访问时间 | `captured_at`（UTC） |
| 读取范围 | `completeness.scope`、`status`、`stop_reason` |
| 完整性 | `manifest.json` 中每个文件的 SHA-256；前置检索记录里的 `manifest_sha256` |
| 工具版本 | `manifest.json` 的 `extractor_version` |
| 页面图像 | `page.png` |
| 引用片段 | 摘录原文并写明所在小节，由所属技能手写 |

## 调研结论的结构

按 [PRISMA 2020](https://www.bmj.com/content/372/bmj.n71) 清单第 5 至 9 项和第 23 项的要求组织：先给结论，再交代范围、来源、检索方式，最后写限制。前置检索结论页的三张表与之对应。

| 内容 | 对应表 | 要求 |
|---|---|---|
| 结论、来源与采用决定 | 表 1 检索结论 | 每条写来源（标题链接和域名）、用途和决定；未采用的写原因；搜索卡片和摘要不列 |
| 范围与检索方式 | 表 2 检索范围与路线 | 列出全部平台、关键词和网址，含没有取得正文的路线 |
| 限制 | 表 3 未覆盖范围 | 没有核实的版本、地区、平台、被拦截或没读到的页面 |

检索日期保存在记录里，页面不写；需要日期时由所属方案的调研页按它的版式写入。一份调研页至少回答：用了哪些来源、各自什么级别、哪些结论只有单一来源、哪些没有核实。
